Observed at the SL-004 audit (RV-028 F-2). `.doctrine/slice/004/decision-amendments.md` mapped six knowledge records for a rename, per record a facet table and a prose table, and each record closed with an explicit "Unaffected rationale, retained explicitly" list. For DEC-007 that list claimed "all four rejected alternatives" were retained — and the first of the four read "Fully key-sorted entities (no `id`-first) — rejected: `id` is what a reader looks for first…", i.e. the very rule the amendment was reversing. The record's `title` and derived `slug` also still named the old ordering and appeared in neither table.

The failure mode is structural, not careless: a thorough-looking mapping earns trust, so the reviewer reads the *tables* instead of the *record*. The confident "everything else is retained" sentence is the part that suppresses the check.

Rule: audit a proposed amendment by enumerating the target's occurrences of the token being moved (`grep -n '"id"\|`id`\|id-first' <record>`), then marking each hit covered / retained / missed. Never take the proposal's own coverage claim as evidence — the proposal enumerates what its author noticed, which is the same set the audit is supposed to test.
